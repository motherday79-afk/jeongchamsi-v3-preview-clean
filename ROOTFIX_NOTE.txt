JCV3 STORAGE LAYER HARD ROOTFIX — 2026-08-30

ROOT CAUSE
- Upstash rejects HTTP request bodies above 10,485,760 bytes.
- Previous fixes could split multiple MSET entries, but a single JSON value above the limit was still sent as one request.
- This is why the same max_request_size_exceeded message could survive route-level patches.

FIX
- setJSON: values above 5.5MB are transparently stored as base64 chunks + a small manifest.
- getJSON/mgetJSON: chunk manifests are transparently reassembled and parsed, so callers do not change.
- msetJSON: oversized individual values are routed through chunked storage; smaller values stay byte-budgeted.
- pipeline: aggregate pipeline requests are byte-budgeted and split below 6MB.
- scanDomains/deleteDomains compatibility retained.

SCOPE
- Runtime change: lib/v3/redis.js only.
- No AGE/GENDER calculation changes.
- No NOW scoring changes.
- No data deletion or migration required.
